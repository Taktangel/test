# Trader backtest: дизайн

Дата: 2026-11-03

## Цель

Проверить на истории две стратегии из пакета [trader-skill](https://github.com/Jakeschincariol/trader-skill)
и регулярно (раз в неделю, в GitHub Actions) обновлять статистику:

- сколько сделок закрылось в плюсе и сколько в минусе;
- сколько сделок обогнало S&P 500 (SPY) за то же окно и сколько отстало;
- итоговая доходность стратегии против SPY.

Это исследовательский инструмент. Он не торгует, не подключается к брокеру и не даёт рекомендаций.

## Вне рамок

- Торговля, в том числе на бумажном счёте (форвард-тест — возможный следующий проект).
- Шорты, опционы, плечо.
- Сенат (только Палата представителей).
- Комиссии и проскальзывание (в первой версии считаем нулевыми; отмечаем это в отчёте).

## Стратегии

### Copycat (13F)

- Источник: все 13F-HR с 2014-01-01 по 23 фондам из `filers.json` скилла.
- Сигнал: дата публикации отчёта (filing date), а не конец квартала.
- Вход: цена закрытия следующего торгового дня после публикации.
- Портфель: топ-10 позиций фонда по стоимости. Два варианта весов, оба считаются:
  `equal` (по 10 %) и `fund` (веса фонда, нормированные на топ-10).
- Выход: цена закрытия следующего торгового дня после публикации следующего 13F-HR этого фонда.
  Если следующего отчёта нет (фонд перестал подавать или следующий ещё не вышел), позиция
  закрывается по закрытию первого торгового дня не раньше чем через 120 календарных дней
  после публикации.
- Список подач берётся полностью: `filings.recent` из submissions API плюс старые
  страницы из `filings.files` (иначе у активных фирм история обрезается).
- В топ-10 берутся акции (без опционов) по стоимости, даже если тикер не найден:
  такие позиции становятся сделками `no_price`, а не заменяются следующими по размеру
  (иначе в выборку тихо попадает ошибка выжившего).
- Сделка = одна позиция за один период между отчётами. Если тикер остаётся в топ-10
  несколько кварталов подряд, это несколько сделок (по одной на период).
- Поправки (13F-HR/A) игнорируются; берём первоначальный отчёт за квартал.

### Congress (PTR)

- Источник: годовые индексы House Clerk (`{year}FD.zip`) с 2014 года, PTR членов из `members.json`.
- Стартовый список: Nancy Pelosi, Josh Gottheimer, Ro Khanna, Michael McCaul, Dan Meuser,
  Mark Green. Список редактируется без изменения кода.
- Учитываются только акции (не опционы, не облигации, не фонды без тикера).
- Сигнал: дата подачи PTR (не дата самой сделки конгрессмена).
- Вход: цена закрытия следующего торгового дня после даты подачи, только по покупкам.
- Выход, четыре варианта, все считаются:
  `hold30`, `hold90`, `hold180` (30/90/180 календарных дней после входа,
  выход по закрытию первого торгового дня не раньше этой даты) и `until_sale`
  (по закрытию следующего торгового дня после подачи PTR с продажей того же тикера тем же членом;
  если продажи нет за 365 дней, выход через 365 дней).
- Сумма сделки: в PTR указан диапазон. Для доли выигрышных сделок вес не важен.
  Для портфельной кривой — равный вес на каждую открытую сделку.

## Статусы сделок

- `ok` — сделка закрыта. Если тикер перестал торговаться до даты выхода, выход по последней
  доступной цене, `note = last_available`.
- `open` — дата выхода ещё не наступила. Оценивается по последней цене, входит в кривую
  капитала, но не в доли выигрышных сделок.
- `pending` — сигнал вышел, а торгового дня для входа ещё нет. Нигде не учитывается.
- `no_price` — нет тикера или цен. Только счётчик в отчёте.

## Метрики

Для каждой сделки:

- `ret` — доходность с учётом сплитов и дивидендов (скорректированная цена закрытия);
- `spy_ret` — доходность SPY за то же окно;
- `win_abs` = `ret > 0`;
- `win_spy` = `ret > spy_ret`.

Агрегаты по каждому фонду, члену Палаты, варианту стратегии и в целом:

- число сделок, `win_abs` %, `win_spy` %;
- средняя и медианная доходность сделки, средний избыток над SPY;
- для портфельной кривой: CAGR стратегии и SPY, максимальная просадка;
- число сделок без цены (`no_price`) — отдельной строкой.

Портфельная кривая для Copycat: капитал на каждый период делится по весам варианта.
Для Congress: равный вес между всеми сделками, открытыми в данный день, свободные деньги лежат
в кэше под 0 %.

## Архитектура

```
trader-backtest/
  vendor/            edgar13f.py, ptr.py, filers.json, share_classes.json из скилла + LICENSE (MIT)
  members.json       список членов Палаты
  config.json        старт периода, топ-N, сроки удержания
  backtest/
    fetch_13f.py     фонды → events_13f.csv (fund, filed, ticker, weight)
    fetch_ptr.py     члены → trades_ptr.csv (member, filed, ticker, side, amount_range)
    prices.py        тикер → дневные скорректированные цены, кеш в data/prices/*.csv
    strategies.py    события → список сделок (entry/exit дата и цена)
    metrics.py       сделки → агрегаты и кривые
    report.py        reports/latest.md, trades.csv, summary.json, equity.png
    run.py           точка входа: fetch → prices → strategies → metrics → report
  tests/
  .github/workflows/backtest.yml
```

Каждый модуль читает и пишет простые CSV/JSON, поэтому шаги можно запускать и проверять по отдельности.

### Данные о ценах

- Основной источник: Yahoo chart API (`query1.finance.yahoo.com/v8/finance/chart`), дневные, скорректированные.
- Запасной: stooq CSV.
- Кеш на диске; при повторном запуске докачиваются только новые дни.
- Неофициальный API Yahoo может сломаться — тогда используется stooq, а при отказе обоих тикер
  получает `no_price`.

### Сопоставление тикеров

- 13F: CUSIP → тикер через логику `edgar13f.py` (company_tickers SEC + OpenFIGI, ключ OpenFIGI опционален).
- Несколько классов акций (GOOGL/GOOG) склеиваются по `share_classes.json`.
- PTR: тикер из описания актива, как его извлекает `ptr.py`.

## Облако (GitHub Actions)

- `on: schedule` раз в неделю (воскресенье, 06:00 UTC) и `workflow_dispatch`.
- Секреты: `SEC_USER_AGENT` (обязательно, «Имя email»), `OPENFIGI_API_KEY` (необязательно).
- `actions/cache` для `data/` (цены, скачанные отчёты и PDF).
- После прогона workflow коммитит `reports/` в репо от имени `github-actions[bot]`.
- Ограничение SEC: не более 10 запросов в секунду, User-Agent обязателен.

## Обработка ошибок

- Нет цены на вход или выход → сделка `no_price`, в отчёте отдельная строка, в метрики не входит.
- PDF не разобрался или в нём нет текста (старые PTR бывают сканами; в CI ставится
  `poppler-utils` ради `pdftotext`) → запись в `reports/errors.log`, PDF пропускается,
  прогон продолжается.
- Сетевая ошибка → до 3 повторов с паузой; затем источник пропускается и это видно в логе.
- Прогон падает целиком только если не удалось получить цены SPY (без них нечего сравнивать).

## Тестирование

- pytest, офлайн.
- Фикстуры 13F и PTR — из `tests/fixtures` скилла.
- Синтетические цены (несколько тикеров, ручные числа), на которых доходность, `win_abs`,
  `win_spy`, CAGR и просадка проверяются вручную.
- Тест на отсутствие заглядывания в будущее: вход никогда не раньше даты публикации + 1 торговый день.

## Известные ограничения (пишутся в шапку отчёта)

- 13F показывает позиции с задержкой до 45 дней и только длинные позиции в US-акциях.
- Суммы в PTR — диапазоны; сроки подачи до 45 дней после сделки.
- Ошибка выжившего: по делистингованным тикерам цен может не быть (видно по `no_price`).
- Комиссии и налоги не учтены.
- Это не финансовый совет.
